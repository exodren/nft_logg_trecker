# Отчёт: Фаза 4 — Kartoshka API Provider, очередь, двухэтапная фильтрация

Дата: 2026-11-10. Задачи K4.2–K4.8, T3.5, F.1–F.4.

## Сделано
- **Контракт** (`app/providers/base.py`): `OwnerData` (статус, Telegram ID, username, отображаемое имя, приватность, причина, HTTP-код, billing, raw), `OwnerStatus` FOUND/HIDDEN/NOT_FOUND/UNAVAILABLE/ERROR, протокол `OwnerDataProvider`.
- **`KartoshkaApiProvider`** (`app/providers/kartoshka.py`): `GET /v1/gift/{slug}`, Bearer, aiohttp с пулом соединений, Semaphore (`MAX_CONCURRENT_API_REQUESTS`), темп 1 запрос/с (нижний документированный лимит), таймаут 15 с, retry с backoff только для сети, 429 (`Retry-After`, максимум 60 с) и 5xx — не более 3 попыток. 400/401/402/404 не повторяются. 401 выключает провайдер. `/v1/ping` (бесплатно) — узнать квоту, `/v1/pricing` — цена. `/who` и `/owners/search` отсутствуют.
- **Схема ответа не выдумана**: поля владельца читает `OwnerMapper`. Сейчас стоит `UnverifiedSchemaMapper` — он ничего не угадывает, отдаёт `UNAVAILABLE/schema_unverified` и сохраняет raw; провайдер `ready=False`, конвейер его не вызывает. После K4.1b пишется проверенный маппер.
- **`MockProvider`** (`app/providers/mock.py`).
- **API Usage Manager** (`app/services/api_usage.py`): счётчики по UTC-суткам (всего, успешные, ошибки, бесплатные, платные, TON), стоимость из `X-Request-Cost`, квота из `X-Free-Remaining`, баланс из `X-Balance`. Перед первым запросом суток квота узнаётся бесплатным `/v1/ping` (квота общая на все приложения аккаунта), каждая разрешённая бесплатная попытка резервирует единицу квоты. `DAILY_API_BUDGET_TON=0` → только бесплатная квота. Предупреждение админу при 80 % бюджета, остановка при 100 %, при 402 и 401; `resume()` после пополнения. Отчёт: запросы, успешные, ошибки, потрачено, остаток, средняя стоимость.
- **Кэш** (`app/services/cache.py`): FOUND/HIDDEN/NOT_FOUND свежи `API_CACHE_TTL`, UNAVAILABLE/ERROR не кэшируются; владелец по `telegram_id` (username может меняться).
- **Сценарий** (`app/services/enrichment.py`): кэш → провайдер готов? → квота/бюджет → запрос → учёт → кэш.
- **Очередь** (`app/services/queue.py`): приоритеты HIGH (новые) / LOW (backfill), дедупликация с объединением флагов, захват условным UPDATE, backoff `30 с × 2^n`, `failed` после 5 попыток, `defer` не тратит попытку, `recover()` после падения, `retry_failed`, `wake_deferred`.
- **Двухэтапная фильтрация** (`app/services/filters.py`, `pipeline.py`): этап 1 в транзакции сканера (нет подходящих → `NOT_NEEDED`, запроса нет); задача → кэш/бюджет/запрос → этап 2 → строки `notifications`. Без данных владельца пользователи с критериями владельца ждут, остальные получают карточку сразу; при повторе дублей нет. Backfill для нового фильтра — низкий приоритет, учитывает кэш и бюджет, не рассылает уведомления. Неактивный листинг закрывает задачу без запроса.
