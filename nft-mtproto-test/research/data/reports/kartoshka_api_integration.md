## 2. Метод `GET /v1/gift/{ref}`

- `ref`: `Slug-N` (как в `t.me/nft/…`, пример `PlushPepe-1`) или числовой id подарка. Для нас `ref` = `slug` из MTProto (`StarGiftUnique.slug`, формат `IonGem-3185`).
- Описание из документации: один подарок со всеми атрибутами и их редкостью (у crafted — `rarityTier`), **текущим владельцем**, продажей (включая внешние маркеты), TON-адресами, данными минта и `estimate`.
- **Схема JSON не опубликована.** Поля владельца, признак скрытого владельца и форма ответа неизвестны. Пробел закрывается задачей K4.1b (реальные ответы).
- Документированные признаки приватности: события скрытых участников приходят с `"hidden": true`, история скрытого профиля пустая с флагом `hiddenByOwner`. Применяются ли они к `/v1/gift/{ref}`, не описано.

Прочие методы (`/v1/owner/{ref}`, `/v1/gift/{ref}/history`, `/v1/resolve`, `/v1/gifts`, `/v1/sales`, `/v1/floors`, `/v1/stats`, `/v1/leaderboards/*`, WebSocket `wss://live.see.tg/v1/ws`) в MVP не используются (§2.3).
`/v1/gift/{ref}/who`, `/v1/owner/{ref}/who`, `/v1/owners/search` — **запрещены в MVP** (§2.2): ищут людей за скрытыми профилями, 0.01 TON.

## 3. Ошибки

| Код | Значение по документации | Наша обработка (K4.5) |
|---|---|---|
| 400 | нет обязательного параметра или он некорректен | `ERROR`, без повтора |
| 401 | токен не передан, не существует или сброшен | `ERROR`, остановка запросов, уведомление админа |
| 402 | бесплатные запросы кончились, баланса не хватает; в ответе — когда вернутся бесплатные и баланс | `UNAVAILABLE`, остановка платных запросов, уведомление админа, `DEFERRED` |
| 404 | метод или объект не найден | `NOT_FOUND` (не списывается) |
| 429 | превышен лимит, `Retry-After` | ожидание `Retry-After`, ограниченный повтор |
| 500 | внутренняя ошибка | retry с backoff, затем `UNAVAILABLE` |

## 4. Лимиты

- С балансом: до 20 запросов/с на приложение. Без баланса: 1 запрос/с, 60 в минуту (token bucket).
- Каждый ответ: `X-RateLimit-Limit`, `X-RateLimit-Remaining`; при 429 — `Retry-After` (секунды).

## 5. Тарифы и расходы

`GET /v1/pricing` (без токена), 2026-11-10:

```json
{"currency":"TON","freePerDay":100,"pricePerRequest":"0.00005","pricePerRequestNano":50000,
 "pricedMethods":{"gift.who":{"freeQuota":false,"multiplier":200,"pricePerRequest":"0.01"}, "owner.who":{…}, "owners.search":{…}},
 "rps":{"withBalance":20,"withoutBalance":1},"tonUsd":1.034}
```

Сверка с §2.4 промпта: 100 бесплатных в сутки и 0.00005 TON за запрос — **совпадает**.

- Бесплатная квота общая на все приложения аккаунта, сбрасывается в **00:00 UTC**.
- Списываются только 2xx. Ошибки (400, 404, 429, 5xx), `/v1/ping`, `/v1/me` — бесплатны. Сначала тратятся бесплатные запросы.
- Заголовки каждого ответа: `X-Free-Remaining`, `X-Request-Cost`, `X-Balance` (TON). Подробно — `/v1/me`, блок `billing`.
- Оценка нагрузки §2.4 до двухэтапной фильтрации: 3 000–7 000 запросов в сутки ≈ 0,145–0,345 TON в сутки. Фильтр этапа 1 (§20) снижает это число.

Учёт в API Usage Manager (K4.7): фактическая стоимость — из `X-Request-Cost`, остаток квоты — `X-Free-Remaining`, баланс — `X-Balance`; при отсутствии заголовков — из `/v1/pricing`. Тарифы в код не зашиваются.

## 6. Правила сервиса (rules.js)

Нарушение любого правила блокирует весь аккаунт see.tg, остаток баланса не возвращается.

1. Не строить конкурента see.tg (поиск подарков, каталог владельцев как суть продукта).
2. Не выкачивать базу: массовый парсинг запрещён, особенно историй; обход лимитов пулами приложений, аккаунтов, IP запрещён.
3. Не перепродавать доступ к данным.
4. Никакого скама.
5. Только настоящие приложения: реальные название, ссылка, назначение; «test» в названии блокируется.
6. **Указывать источник:** если данные видны в публичном проекте (бот), рядом — «Данные: see.tg» со ссылкой на https://see.tg. Реализуется в карточке и `/help` (T5.2, T5.5).

Как это учтено: двухэтапная фильтрация (§20) и кэш (K4.8) исключают массовый сбор; один ключ, без пулов; `/who` и `/owners/search` не используются; ссылка на see.tg в карточке.
