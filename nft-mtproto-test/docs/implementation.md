# Что реализовано

Состояние на 2026-11-10. Требования: `актуальный промпт.md` (+ §20). План и статусы: `TASKS.md`. Тесты: `pytest` — **220 passed**. Ручная проверка: `docs/manual_test_plan.md`. Журнал сессии: `docs/session_2026-11-10.md`.

## Поток данных

```
MTProto (getResaleStarGifts, только чтение)
  → Parser → БД: gifts + listings (сохраняются всегда)
  → Этап A: фильтры NFT (коллекция, цена, модель, фон, паттерн)
       никому не подходит → NOT_NEEDED, запроса к Kartoshka нет
       подходит хотя бы одному → очередь owner_lookup
  → кэш владельца → квота/бюджет → Kartoshka GET /v1/gift/{slug}
  → нормализация: владелец учитывается только с username
  → Этап B: условия владельца (есть username, есть ID, конкретный @username / ID)
  → NFT-уведомление подписчику (личные сообщения)
```

Поиск всегда идёт в направлении NFT → владелец. NFT по username или Telegram ID не ищутся.

## Правила, зафиксированные по ходу работы

1. **Источник владельцев** — только официальный API kartoshka.free (из мини-аппа see.tg). Внутренний GraphQL See.TG не используется.
2. **Двухэтапная фильтрация (§20)**: платный запрос — только если NFT подходит хотя бы одному пользователю по характеристикам NFT.
3. **Владелец только с username**: ID без username не сохраняется в `owners`, не показывается и не даёт совпадений; результат `NO_USERNAME` кэшируется, повторной оплаты нет.
4. **Скрытый владелец** в Telegram не упоминается; строка «🔒 Владелец скрыл профиль» — только в `logs/app.log`.
5. **Три потока**: NFT-уведомления → подписчикам; служебные логи → только `LOG_GROUP_ID`; локальный лог → `logs/app.log`. Личных служебных сообщений админам нет.
6. **Платные запросы** разрешены в пределах `DAILY_API_BUDGET_TON`. Значение по умолчанию в коде — 0 (только 100 бесплатных в сутки); для работы и ручных тестов бюджет задаётся в `.env` (например 0.05 TON ≈ 1 000 запросов).
7. **Уведомления нового пользователя выключены**, пока он сам их не включит.
8. Поля ответа Kartoshka не угадываются: провайдер не вызывается, пока маппер не подтверждён реальными ответами.

## Известные ограничения

- Опрос первых страниц: листинг, ушедший со страницы 1 крупного типа, через 24 ч становится UNKNOWN, а не INACTIVE.
- Снятие и повторное выставление тем же продавцом между сканами — один эпизод.
- Пустой фильтр с включёнными уведомлениями = запрос владельца для каждого нового листинга (сдерживает бюджет).
- Тестовые фикстуры и `chillflame*` не в Git (реальные данные); в чистом клоне тесты парсера/сканера/конвейера требуют `tests/fixtures/resale/`.
